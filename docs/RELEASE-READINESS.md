## Findings

- `src/main.ts:190-202,260-282,347-373`: focused editor derives query in its own update; other panes receive a debounced effect. No source dispatch in that path. Stale pane instances are dropped on destroy; pending timer is cancelled in `onunload()` (`107-115`). JSDOM integration tests cover source dispatch and unload, not Obsidian leaf lifecycle.
- `src/main.ts:284-334,375-423,592-648`: cursor matching uses Unicode letters/numbers and extra characters; literal selection is at most 500 UTF-16 units, with no multiline, and whitespace-only single-line selection is currently accepted. Whole-word boundaries inspect code points; matching scans visible ranges and caps accepted matches. Supplementary symbols and partial viewport matches need expanded host tests.
- `src/main.ts:204-226`: the Android guard originally deferred an explicit Clear while selection remained non-empty, leaving source marks. A regression scenario/test preceded the narrow fix: explicit Clear/Disable now removes marks while normal selection updates defer. The guard cannot guarantee the absence of unrelated Obsidian DOM changes.
- `src/main.ts:425-439`: `editor.cm` is a compatibility access documented for editor extensions but not part of public `Editor` types; the isolated `@ts-expect-error` remains. Active-file changes without a CM transaction, hidden tabs reopened, and new panes require manual host testing; `visibleRanges` is not leaf visibility.
- `styles.css:9-28`: `color-mix` may vary with WebView; `.markdown-source-view.mod-cm6 .cm-scroller` scroll-anchor override affects other CM6 editor panes and is retained from user-tested baseline until host comparisons justify narrowing. No assertion that Shiki causes scrollbar jumps: only owner-observed correlation and improvement after restarting Shiki.
- `src/main.ts` imports only Obsidian and host CodeMirror; `esbuild.config.mjs` externalizes them and Lezer, with `minify: false`. No runtime network, telemetry, eval or note writes were found in the current source. CI still needs to run on GitHub.
- Owner-approved first-public-release change `align-command-ids-for-first-release` replaces unpublished local command IDs with `toggle-highlighting` and `clear-highlighting`, avoiding duplication of the automatically prefixed plugin ID. Local unpublished hotkeys may require rebinding; there are no public releases to migrate. The pre-1.13 settings tab still triggers an advisory lint warning. No mass rule disable is used.
